# Лабораторная работа: генератор паролей с настраиваемыми политиками

# Вариант 1

## Общая идея

Разработать консольное приложение для составления политик генерации паролей и генерации паролей по правилам политики.

Пользователь должен иметь возможность выбрать политику, сгенерировать по ней пароль и проверить произвольный пароль на соответствие заданным требованиям.

---

# 1. Управление приложением

Приложение должно управляться через текстовые команды или меню.

Минимальный набор операций:

1. Показать доступные политики.
2. Показать параметры выбранной политики.
3. Сгенерировать пароль по выбранной политике.
4. Проверить пароль на соответствие политике.
5. Перезагрузить конфигурацию.
6. Составить новую политику.
7. Завершить работу.

---

# 2. Политики генерации паролей +

Конфигурационный файл должен содержать одну или несколько именованных политик. Каждая политика описывает правила, которым должен соответствовать пароль.

В политике должны поддерживаться как минимум следующие параметры:

* название;
* текстовое описание;
* минимальная и максимальная длина;
* длина, используемая при генерации по умолчанию;
* разрешённые группы символов;
* минимальное количество символов каждой группы;
* запрещённые символы;
* возможность повторения символов;
* максимальное количество одинаковых символов подряд;
* возможность использования пробелов;
* список запрещённых подстрок.

Основные группы символов:

* строчные латинские буквы;
* прописные латинские буквы;
* цифры;
* специальные символы.

Допускается поддержка дополнительных групп, например:

* кириллические буквы;
* шестнадцатеричные цифры;
* символы, заданные пользователем;
* разделители.

# 4. Просмотр политик

Пользователь должен иметь возможность получить список доступных политик.

Пример:

```text
> policies

Доступные политики:

Название   Длина    Описание
default    12–64    Обычный пароль для сайта
pin        4–8      Цифровой PIN-код
wifi       16–32    Пароль для домашней сети Wi-Fi
```

Также пользователь должен иметь возможность просмотреть полное описание конкретной политики:

```text
> show-policy wifi

Политика: wifi
Описание: Пароль для домашней сети Wi-Fi

Длина по умолчанию: 20
Допустимая длина: от 16 до 32

Разрешены:
- строчные буквы, не менее 4;
- прописные буквы, не менее 2;
- цифры, не менее 2.

Запрещённые символы: 0 O 1 I l
Повторение символов: запрещено
Пробелы: запрещены
```

# 5. Генерация пароля +

Пользователь должен иметь возможность сгенерировать пароль по имени политики.

Пример:

```text
> generate default

Политика: default
Длина: 16
Пароль: rZ8!mQ4_wK2#tNp7
```

Если имя политики не указано, должна использоваться политика по умолчанию, заданная в конфигурации.

Пользователь должен иметь возможность переопределить длину пароля:

```text
> generate default --length 24
```

Указанная длина должна находиться в пределах, разрешённых политикой.

Сгенерированный пароль должен гарантированно соответствовать всем требованиям выбранной политики.

---

# 6. Проверка пароля

Пользователь должен иметь возможность проверить произвольный пароль на соответствие выбранной политике.

Проверка должна выдавать результат отдельно для каждого требования. Сообщения вида «пароль неправильный» без объяснения причины недостаточно.

Пример:

```text
> check default
Введите пароль: ********

Результат проверки по политике default:

[+] Длина находится в пределах от 12 до 64
[+] Содержит строчную букву
[+] Содержит прописную букву
[+] Содержит цифру
[-] Не содержит специального символа
[+] Не содержит запрещённых символов
[+] Не содержит запрещённых подстрок
[+] Не содержит более двух одинаковых символов подряд

Пароль не соответствует политике default.
```

---

# 7. Проверка корректности политики

Перед использованием конфигурации приложение должно проверить каждую политику на непротиворечивость.

Необходимо обнаруживать как минимум следующие ошибки:

* минимальная длина меньше единицы;
* максимальная длина меньше минимальной;
* длина по умолчанию находится за допустимыми пределами;
* не включена ни одна группа символов;
* минимальное количество символов группы является отрицательным;
* минимальное количество задано для выключенной группы;
* сумма обязательных количеств превышает максимальную длину;
* разрешённый символ одновременно указан как запрещённый;
* после исключения запрещённых символов группа становится пустой;
* повторения запрещены, но доступных символов недостаточно для создания пароля требуемой длины;
* максимальное количество одинаковых символов подряд меньше единицы;
* политика по умолчанию отсутствует.

При наличии некорректной политики приложение не должно переходить к генерации паролей по этой политике.

Сообщение об ошибке должно содержать:

* имя политики;
* проблемный параметр;
* объяснение причины;
* по возможности — способ исправления.

Пример:

```text
Ошибка в политике "pin".

Сумма обязательных символов: 6
Максимальная длина пароля: 4

Уменьшите minimumCount для группы digits
или увеличьте maximumLength.
```

# 8. Перезагрузка конфигурации

Пользователь должен иметь возможность изменить конфигурационный файл во время работы приложения, а затем выполнить команду перезагрузки:

```text
> reload
```

При успешной перезагрузке новые политики должны стать доступны без перезапуска приложения.

Если новый конфигурационный файл содержит ошибку:

* приложение должно вывести описание ошибки;
* ранее загруженная корректная конфигурация должна продолжить использоваться;
* ошибка должна быть записана в журнал.

---

# 9. Мониторинг и журналирование

Приложение должно вести журнал своей работы в отдельном файле.

В журнал необходимо записывать:

* запуск и завершение приложения;
* загрузку и валидацию конфигураций;
* обнаруженные ошибки в политиках;
* запрос на генерацию пароля;
* имя использованной политики;
* длину сгенерированного пароля;
* выполнение проверки пароля;
* результат проверки без указания самого пароля;
* неизвестные команды;
* некорректные параметры команд;
* внутренние ошибки приложения.

Пример журнала:

```text
2026-09-12 15:40:01 INFO  Приложение запущено
2026-09-12 15:40:01 INFO  Загружено политик: 3
2026-09-12 15:41:02 INFO  Выполнена генерация: policy=default, length=16
2026-09-12 15:42:18 INFO  Выполнена проверка: policy=default, result=failed
2026-09-12 15:44:03 WARN  Неизвестная команда: generete
2026-09-12 15:45:11 INFO  Конфигурация успешно перезагружена
2026-09-12 15:48:30 INFO  Приложение завершено
```

В журнал запрещено записывать:

* сгенерированные пароли;
* проверяемые пароли;
* полный пользовательский ввод, если он может содержать пароль.

Журнал должен дополняться при каждом запуске, а не перезаписываться полностью.

---

# 10. Обработка ошибок

Приложение должно корректно обрабатывать как минимум следующие ситуации:

* введена неизвестная команда;
* не указано имя политики;
* указанная политика не существует;
* длина не является целым числом;
* длина находится за пределами политики;
* невозможно выполнить требования политики;
* конфигурационный файл отсутствует;
* конфигурационный файл имеет неправильный формат;
* конфигурация не содержит политик;
* политика содержит противоречивые настройки;
* файл журнала невозможно открыть или изменить;
* конфигурацию невозможно перезагрузить.

Некорректный пользовательский ввод не должен приводить к аварийному завершению приложения.

Сообщения об ошибках должны объяснять причину проблемы.

Пример:

```text
Ошибка: длина 8 не разрешена политикой "default".

Допустимая длина: от 12 до 64.

Пример:
generate default --length 16
```
